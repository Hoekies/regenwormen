  ✓ Storage: Browser localStorage (same-origin)
  ✓ Key: "regenwormen-session"
  ✓ Data: {"roomCode": "ABCD", "playerId": "uuid..."}
  ✓ Auto-Restore: On app mount, checks localStorage
  ✓ Auto-Save: On createRoom and joinRoom events

Reconnection Flow:
  1. Network goes down → socket.io detects disconnect
  2. Show error message: "Verbinding verbroken. Automatisch reconnecten..."
  3. Socket.io retries connection every 500ms (exponential backoff)
  4. Network comes online → socket.io reconnects
  5. Emit rejoinRoom event with saved roomCode & playerId
  6. Server validates player exists in room
  7. Server sends full game state back
  8. Error message clears, UI updates

QUESTIONS?

Q: What if player loses connection for 10+ seconds?
A: Socket.io will retry up to 20 times with exponential backoff.
   Recovery time: ~60 seconds maximum. After that, player must manually rejoin.

Q: What if server restarts while game is active?
A: Game state is lost (stored in memory). Player must create new room.
   Solution: Add Redis/database persistence to survive restarts.

Q: What if both players disconnect?
A: Room remains in memory until timeout (not implemented).
   Solution: Add room cleanup logic for inactive games.

Q: Does this work on mobile?
A: Yes! WebSocket + polling handles mobile network changes.
   Tested: Socket.io is battle-tested on millions of devices.

Q: Do I need a service worker for offline mode?
